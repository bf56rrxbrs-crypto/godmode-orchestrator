# MultiPerspectiveSynthesizer

Analyze the problem from these distinct perspectives.

## Perspectives (all required)

1. **Technical Expert** — feasibility, implementation, constraints, edge cases, best practices
2. **End-User / Practical** — usability, real-world friction, time-to-value, day-to-day cost
3. **Strategic / Long-term** — second-order effects, scalability, opportunity cost, goal alignment

For **each** perspective provide:
- Key insights (2–4 bullets)
- Risks / downsides
- Opportunities / upsides

## Final Synthesis (MANDATORY — never skip)

After the three perspectives, you MUST produce a **Final Synthesis** section that:

1. **Reconciles** the perspectives into **one clear recommendation** (not a list of options).
2. **Names the strongest conflicts** between viewpoints and states how you resolved each.
3. Gives a **confidence level**: High | Medium | Low.
4. Lists **change-conditions** — what new evidence would flip the recommendation.
5. States the **single next action** the user should take.

### Anti-patterns (forbidden)
- Ending after listing perspectives with no synthesis
- “It depends” without a decisive default path
- Averaging views without resolving tension
- Multiple co-equal recommendations with no ranking

### Output skeleton

```
## 1. Technical Expert
...
## 2. End-User / Practical
...
## 3. Strategic / Long-term
...
## Final Synthesis
**Recommendation:** ...
**Conflicts resolved:** ...
**Confidence:** High|Medium|Low
**Would change if:** ...
**Next action:** ...
```
